Changelog v6.0.1

v6.0.1 Release date · 2026-08-18 · Foundry VTT 14

Maintenance release

v6.0.1 stabilizes the Foundry VTT v14 and ApplicationV2 changes delivered in v6.0.0. It contains corrective work only; no data migration is associated with this release.

✦

Player-heroes & Communities

  • Shadow Scars can once again be edited from the Resources tab of the Player-hero sheet. Temporary Shadow remains managed from the sidebar, while total Shadow continues to be calculated automatically. #621
  • The maximum number of Fellowship Points is no longer reset to 0 when a Player-hero recovers Hope during a short or long rest. #615
  • Eye Awareness information is no longer shown to players when the system setting restricts its visibility to the Lore-master. #616
✦

Journeys & Journey Logs

  • Small Companies can once again assign multiple journey roles to the same Player-hero. Form submissions now preserve the other array entries instead of overwriting them. #618
  • Closing an Item sheet immediately after editing now waits for already queued saves to complete. This notably prevents the loss of a recently entered Company member name in a Journey Log. #623
✦

Sheets & Interface

  • Image editing has been restored on ApplicationV2 Item sheets, for both world Items and Items embedded in an Actor. The action remains restricted to users with edit permission and retains the expected compatibility with Tokenizer and Tokenizer2. #624
  • ApplicationV2 Item sheets are once again resizable in Foundry VTT v14. #612
  • TOR2E-specific heading styles are now scoped to the system interface and no longer override Foundry VTT’s native heading styles. #611
  • The Connections list on the Community sheet is now scrollable when many entries overflow the panel. #610
  • Document image display — portrait and token — is now consistent across all sheet types. #651
  • The Load and Shadow meters on the Character Sheet have an improved layout that better reflects their visual hierarchy. #652
✦

Diamond Consistency

The diamond components used across TOR2E now follow one explicit visual and semantic state contract.

State model

  • Diamond state design tokens (--tor2e-diamond-*) were introduced in tokens.less, together with semantic CSS classes state--editable, state--readonly, and state--computed. #653
  • Read-only diamond center values now carry the explicit state--readonly class. #654
  • Item-projection diamonds for Armour, Shield, and Headgear are classified as state--readonly. #655
  • TN, Load, and Shadow diamonds carry the state--computed class. #656
  • All editable diamond components carry the state--editable class. #657
  • Diamond state contract tests were extended and the state convention was documented. #658
✦

Technical Quality

  • Pre-existing ESLint warnings related to line length, JSDoc documentation, and parameter ordering have been resolved, restoring a clean lint baseline. #622
  • The Playwright regression suite has been updated around Foundry VTT v14 interaction contracts: centralized document creation, better-scoped selectors, explicit readiness checks, browser-error diagnostics, and cleanup using exact document identifiers. #619 · !477
✦

Duplicate Report

  • #617 reported the same Shadow Scars editing problem addressed by #621 and does not represent a separate fix.
