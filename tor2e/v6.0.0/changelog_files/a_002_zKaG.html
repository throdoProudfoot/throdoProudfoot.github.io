Changelog v6.0.0

v6.0.0 Released 2026-08-15 · Requires Foundry VTT 14+

⚠ Breaking Changes

  • Foundry VTT v14 is now the minimum supported version. v13 and earlier are no longer supported. Do not install this release without upgrading Foundry first.
  • All AppV1 actor and item sheets have been removed. No legacy fallback is provided. If a sheet customisation relied on AppV1 classes, it will need to be updated.
  • A world migration runs automatically on first load. It normalises all actor and item data to the new TypeDataModel schemas. Back up your world before upgrading.
✦

Actor Sheets — Full ApplicationV2 Migration

All remaining actor types are now fully migrated to Foundry's ApplicationV2 engine. Every actor sheet follows the same layout contract: persistent sidebar, vertical icon tab rail, multi-PARTS or mono-PART structure as appropriate.

  • NPC actor — new TypeDataModel schema + ApplicationV2 sheet with sidebar/body layout; default window width widened
  • Lore actor — new TypeDataModel schema + ApplicationV2 sheet aligned with character sheet styling; watermark centered on main content column
  • Community actor — new TypeDataModel schema + ApplicationV2 sheet (see Community section below)
  • Adversary actor — new TypeDataModel schema + ApplicationV2 sheet (see Adversary section below)
✦

Item Sheets — Full ApplicationV2 Migration

Every item type now uses ApplicationV2. The base class Tor2eItemSheetV2 defines shared behaviour; sub-classes handle per-type layout.

Sheet class Item types covered
Tor2eSimpleItemSheetV2trait, song, mount, combat-task, fell-ability, skill
Tor2eEffectEnabledItemSheetV2weapon, miscellaneous, virtues — tabs: details / effects
Tor2eArmourSheetV2armour
Tor2eStandingSheetV2standing
Tor2eRewardSheetV2reward
Tor2eJourneyLogSheetV2journey-log — multi-PARTS, right sidebar, collapsible sections
Tor2eUndertakingSheetV2undertaking

Journey Log sheet refactored to a main + full-height right sidebar grid. Collapsible cards now use native <details>/<summary>. Company and mounts tables use CSS grid.

✦

UI & Design System

  • Two-layer CSS architecture: tokens.less → tokens.css then ui.less → ui.css; never edit the generated CSS files
  • Semantic token system: all components use --tor2e-* tokens; no hardcoded hex or rgba values anywhere
  • @font-face declarations added for custom heading and icon fonts
  • Watermark / background image system unified across all sheets; consistent naming throughout
  • Tab backgrounds support transparency via CSS color-mix()
  • Shared LESS primitives: diamond wrapper and sidebar-section scaffolding (eliminates duplication across sheets)
  • Collapsible sections migrated to native <details>/<summary> elements
  • Soft-grid data table treatment applied to War Gear blocks (adversary sheet) and extended across data tables
  • Shared toggle-switch component extracted from duplicated LESS
  • Font Awesome chevrons replaced with icon markup instead of glyph-code strings
  • Round checkboxes vertically aligned in data tables; favoured checkbox dot centred
