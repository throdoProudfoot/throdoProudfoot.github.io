Changelog v6.2.1

v6.2.1 Release date · 2026-08-30 · Foundry VTT 14

Release date: 2026-08-30

Platform: Foundry VTT 14

Scope: Patch release following v6.2.0

Combat & Token Handling

Fixed

  • Combat context is now resolved from the token's owning TokenDocument instead of relying on the currently viewed encounter.
  • Token HUD behavior remains correct when a token belongs to an encounter other than the one currently displayed.
  • HUD elevation rendering is preserved while resolving the correct encounter context.
  • Combat cleanup remains safe when tokens can be associated with multiple encounters.
  • Combatant retrieval by token was simplified and made more explicit.
  • The isCharacter combatant flag is assigned more reliably.
  • Combat stance initialization is now protected when a Character token is added to combat through the Token HUD.

Refactored

  • Removed the custom Tor2eTokenLayer combat-toggle layer and simplified combatant deletion around Foundry VTT 14 lifecycle behavior.
  • Added architectural documentation for explicit combat-context resolution.
✦

Actor Sheets, Active Effects & Persistence

Fixed

  • Actor form submissions now rebase submitted values against _source before persistence.
  • This prevents effective values contributed by Active Effects from being accidentally written back into source data.
  • Form-data processing and submission error logging were hardened for Foundry VTT sheet updates.
  • Actor image changes are now covered by a dedicated persistence regression test.
  • Adversary sheet submission handling received an additional safeguard for the new source-rebasing lifecycle.

Architecture

  • Sheet/data lifecycle documentation was updated to reflect the rule that submitted values must remain coherent with Actor source data.
  • Guidance for sheet implementations, application architecture and source/effective-value handling was synchronized with the new submission model.
✦

Character, Adversary & Lore Sheets

Fixed / Changed

  • Character Sheet resources now use clearer TOR2E terminology by explicitly distinguishing Load / Fatigue and Shadow / Shadow Points.
  • Resource markup, accessibility labels and resource identifiers were aligned with that terminology.
  • Direct resource diamonds are centered more consistently beneath their headings.
  • Visual separators were restored between Character Sheet tab-content sections.
  • Adversary Sheet layout and structure were refined for more consistent spacing and presentation.
  • Lore Sheet dimensions were adjusted.
  • Adversary and Lore editor backgrounds were refined for better visual consistency.
  • Related structural and CSS regression tests were updated.
✦

Localization

Fixed / Improved

  • Weapon-group names are now localized correctly on NPC and Adversary sheets.
  • Language names for Catalan and Brazilian Portuguese were corrected in the system manifest.
  • Spanish translations received a substantial update covering multiple terms and phrases, including combat tasks, songs, undertakings and reputations.
  • Automated regression coverage now opens Actor and Item sheets in French and checks that translated labels are rendered instead of raw localization keys.
✦

Interface & Styling

Fixed / Changed

  • Actor and Adversary sheet styling was refined for responsiveness, spacing and editor presentation.
  • The Travel card markup received a small structural cleanup.
  • Token styling received a minor adjustment.
  • Pause-message assignment logic was simplified.
✦

Automated Regression Suite

Added / Expanded

  • New E2E coverage for Character token combat-stance initialization.
  • Additional scenarios cover entering combat, leaving combat, valid TOR2E stance values and persistence across scene reloads.
  • New E2E coverage for French localization across Actor and Item sheets.
  • New E2E coverage for Actor image persistence.
  • Reusable Playwright fixtures were introduced for scene and combat setup.
  • Foundry UI helpers were expanded to reduce duplicated setup logic.
  • E2E testing guidelines were documented and consolidated.
✦

CSS Guardrails & Tooling

Changed

  • CSS guardrail reporting and selector analysis were improved.
  • Duplicate-selector and CSS-metric tests were expanded.
  • A manual GitLab CI preview for the next release can now be generated from the develop branch.
✦
